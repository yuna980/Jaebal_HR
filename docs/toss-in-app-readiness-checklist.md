# 토스 인앱 준비 체크리스트

## 1. 목적

이 문서는 현재 서비스를 토스 앱인토스 WebView 미니앱으로 올리기 전에 확인해야 할 항목을 정리한 문서입니다.

목표는 다음과 같습니다.

- 토스 인앱 WebView에서 깨지는 흐름을 미리 찾습니다.
- 심사와 운영에 필요한 문서와 설정을 준비합니다.
- 개인정보, 보안, 장애 확인 체계를 정리합니다.
- 출시 전 반드시 확인할 일을 누락하지 않게 합니다.

## 3. 토스 WebView 필수 점검

| 항목 | 상태 | 확인 방법 |
| --- | --- | --- |
| 첫 진입 화면 | 필요 | 토스 WebView와 비슷한 모바일 WebView에서 `/dashboard`, `/schedule`, `/healing` 직접 진입 확인 |
| 로그인 후 복귀 | 완료 | `/schedule` 등 직접 접근 후 로그인하면 원래 경로로 돌아가는지 확인 |
| 뒤로가기 동작 | 일부 완료 | 야구 목탁 페이지는 이전 페이지 복귀 처리됨. 전체 화면 추가 확인 필요 |
| 하단 네비게이션 | 일부 완료 | iOS Safari, Android Chrome, 토스 WebView에서 하단 잘림 확인 필요 |
| 주소창 없는 환경 | 필요 | 브라우저 주소창 높이에 기대는 UI가 없는지 확인 |
| safe-area 대응 | 필요 | iPhone Dynamic Island, 홈 인디케이터 영역에서 잘림 확인 |
| 터치 반응 | 일부 완료 | 목탁 터치 이미지 전환, 진동 동작 실기기 확인 필요 |
| 로컬 저장소 | 필요 | WebView에서 localStorage 유지 여부 확인 |
| 세션 유지 | 필요 | 앱 종료 후 재진입 시 로그인 상태 유지 확인 |
| 외부 링크 | 필요 | 외부 링크가 있다면 토스 WebView 안에서 열지, 외부 브라우저로 열지 결정 |

## 9. 지금 바로 해야 할 일

1. `docs/service-description.md`를 최신 상태로 업데이트합니다.
2. 개인정보 처리방침 초안을 만듭니다.
3. 이용약관 초안을 만듭니다.
4. 모바일 WebView 실기기 테스트 체크리스트를 실행합니다.
5. Supabase RLS 정책 전체를 다시 점검합니다.
6. 토스 앱인토스 콘솔에서 WebView 등록 요건을 확인합니다.
7. 토스 SDK를 쓸지 결정합니다.

## 10. 현재 리스크

| 관리자 화면 없음 | 운영 확인이 터미널 명령에 의존 | 필요 시 관리자 화면 추가 |
| RLS 전체 점검 미완료 | 개인 데이터 노출 위험 | 정책 전체 리뷰 필요 |
