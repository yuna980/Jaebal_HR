# 서비스 설명서

## 1. 서비스 개요

이 서비스는 KBO 야구 팬을 위한 모바일 중심 웹 서비스입니다. 사용자는 응원 팀을 선택하고, 오늘의 경기 정보, 월별 경기 일정, 팀 성적, 선발/라인업, 구장 정보, 직관 기록, 야구 일기, 푸시 알림, 야구 스트레스 완화용 힐링 화면 등을 사용할 수 있습니다.

운영 URL은 `https://jaebal-hr.vercel.app`입니다.

## 2. 주요 기능

### 2.1 응원 팀 선택

- 첫 화면에서 KBO 팀을 선택합니다.
- 선택한 팀은 브라우저 로컬 저장소와 Supabase 프로필에 저장됩니다.
- 선택된 팀 기준으로 대시보드, 일정, 성적 데이터가 표시됩니다.

### 2.2 대시보드

- 오늘 내 팀 경기 정보를 보여줍니다.
- 홈/원정 팀, 경기 시간, 구장, 경기 상태를 표시합니다.
- 선발 투수와 라인업 정보를 확인할 수 있습니다.
- 상대 팀과의 시즌 상대 전적을 보여줍니다.
- 직관 여부를 기록할 수 있습니다.
- 구장 이동 정보와 먹거리 추천을 간단히 확인할 수 있습니다.

### 2.3 경기 일정

- 월별 KBO 경기 일정을 달력 형태로 보여줍니다.
- 날짜를 선택하면 해당 날짜의 경기 상세 정보를 확인할 수 있습니다.
- 경기 결과, 취소 여부, 승리/패전 투수 정보를 표시합니다.
- 내 팀 경기와 연결된 야구 일기를 작성할 수 있습니다.

### 2.4 마이페이지

- 내 팀 성적을 확인할 수 있습니다.
- 현재 시즌 순위, 승률, 승/패/무 기록을 보여줍니다.
- 작년 같은 시점과 승률 변화를 비교합니다.
- 작성한 야구 일기와 직관 기록을 확인할 수 있습니다.
- 웹 푸시 알림 설정을 관리할 수 있습니다.
- 로그아웃 기능을 제공합니다.

### 2.5 회원가입 및 로그인

- Supabase Auth를 사용해 회원가입과 로그인을 처리합니다.
- 로그인 사용자는 응원 팀, 알림 설정, 일기, 직관 기록을 계정에 저장할 수 있습니다.
- 로그인 전에 특정 링크로 접근한 경우, 로그인 후 원래 접근하려던 경로로 이동합니다.

### 2.6 구장 정보

- KBO 구장별 정보를 제공합니다.
- 구장 주소, 대중교통 안내, 주차장 정보, 먹거리, 굿즈샵 정보를 확인할 수 있습니다.
- Supabase DB에 저장된 구장 데이터를 조회합니다.

### 2.7 야구 일기

- 경기 날짜별로 리뷰와 별점을 기록할 수 있습니다.
- 사용자, 팀, 경기 날짜 기준으로 중복 기록을 막습니다.
- 본인 기록만 조회, 수정, 삭제할 수 있도록 RLS 정책을 사용합니다.

### 2.8 직관 기록

- 특정 경기의 직관 여부를 저장할 수 있습니다.
- 사용자, 팀, 경기 날짜 기준으로 관리합니다.
- 마이페이지와 일정 화면에서 직관 기록을 활용합니다.

### 2.9 푸시 알림

- 웹 푸시 구독을 등록할 수 있습니다.
- 경기 라인업 알림과 직관 팁 알림을 제공합니다.
- 알림 발송 이력은 DB에 저장됩니다.
- Supabase Cron과 Next.js API Route를 통해 예약 발송됩니다.

### 2.10 힐링 센터

- 야구 스트레스 해소용 인터랙션 화면입니다.
- 클릭 횟수와 진행률을 브라우저 로컬 저장소에 저장합니다.
- 날짜가 바뀌면 카운트가 초기화됩니다.
- 모바일에서 터치할 때 약한 진동을 줄 수 있습니다.
- 터치 상태에 따라 목탁 이미지가 바뀌어 두드리는 느낌을 제공합니다.

### 2.11 운영 점검

- KBO 경기 동기화 실행 결과를 `kbo_sync_runs` 테이블에 저장합니다.
- 서버 API 오류를 `server_error_logs` 테이블에 저장합니다.
- 터미널 명령으로 최근 동기화 결과와 서버 오류를 확인할 수 있습니다.

## 3. 개발 언어

- TypeScript: 전체 프론트엔드와 서버 API의 주 개발 언어입니다.
- TSX: React 컴포넌트 작성에 사용됩니다.
- SQL: Supabase 테이블, 정책, 트리거, Cron 설정에 사용됩니다.

- CSS: 전역 스타일과 화면 스타일링에 사용됩니다.

## 5. 사용한 DB 및 구조

### 5.1 DB

- Supabase PostgreSQL을 사용합니다.
- Supabase Auth의 `auth.users`와 서비스 테이블을 연결합니다.
- Row Level Security를 사용해 사용자별 데이터 접근을 제한합니다.

### 5.2 주요 테이블

| 테이블 | 목적 |
| --- | --- |
| `profiles` | 사용자 프로필, 이메일, 응원 팀 저장 |
| `fan_diaries` | 야구 일기, 리뷰, 별점 저장 |
| `attendance_records` | 경기별 직관 여부 저장 |
| `game_schedules` | 시즌 경기 일정 저장 |
| `game_histories` | 종료/취소 경기 결과 저장 |
| `game_lineups` | 경기별 선발 투수와 라인업 저장 |
| `stadiums` | 구장 기본 정보 저장 |
| `stadium_food_vendors` | 구장 먹거리 정보 저장 |
| `stadium_goods_shops` | 구장 굿즈샵 정보 저장 |
| `stadium_parking_lots` | 구장 주차 정보 저장 |
| `notification_preferences` | 사용자 알림 설정 저장 |
| `notification_subscriptions` | 웹 푸시 구독 정보 저장 |
| `notification_deliveries` | 알림 발송 이력 저장 |
| `api_rate_limits` | API 요청 제한 정보 저장 |
| `kbo_sync_runs` | KBO 경기 결과 동기화 실행 기록 저장 |
| `server_error_logs` | 서버 API 에러 로그 저장 |

### 5.3 핵심 관계

- `profiles.id`는 `auth.users.id`를 참조합니다.
- `fan_diaries.user_id`와 `attendance_records.user_id`는 로그인 사용자를 기준으로 저장됩니다.
- `notification_preferences`, `notification_subscriptions`, `notification_deliveries`는 `profiles.id`와 연결됩니다.
- `game_lineups.game_schedule_id`는 `game_schedules.id`와 연결됩니다.
- 구장 관련 상세 테이블은 `stadiums.stadium_name`을 기준으로 연결됩니다.
- `kbo_sync_runs`는 경기 동기화 실행 단위별 처리 수, 저장 수, 이상 데이터 수를 저장합니다.
- `server_error_logs`는 API 경로, 상태 코드, 에러 메시지, 사용자 ID를 저장할 수 있습니다.

### 5.4 보안 구조

- 대부분의 테이블에 RLS가 활성화되어 있습니다.
- 개인 데이터는 본인만 조회, 생성, 수정, 삭제할 수 있습니다.
- 경기 일정, 경기 결과, 라인업, 구장 정보는 공개 조회가 가능합니다.
- API 요청 과다 사용을 막기 위해 `api_rate_limits` 테이블을 사용합니다.
- API는 공개 API, 로그인 필요 API, 크론 전용 API로 구분되어 있습니다.
- 공개 API에는 요청 제한을 적용합니다.
- 로그인 필요 API는 Supabase 세션을 확인합니다.
- 크론 전용 API는 비밀값을 확인한 뒤 실행합니다.
- 보안 헤더를 적용해 iframe 악용, 타입 스니핑, 불필요한 브라우저 권한 사용을 줄입니다.
- 서버 에러 로그 저장 전 토큰, 쿠키, 인증값 등 민감 정보는 `[REDACTED]`로 가립니다.

## 6. 구조에 사용된 서비스

### 6.1 Supabase Auth

- 회원가입, 로그인, 세션 관리에 사용됩니다.
- 신규 사용자 생성 시 `profiles` 테이블과 동기화됩니다.

### 6.2 Supabase PostgreSQL

- 사용자 데이터, 경기 데이터, 구장 데이터, 알림 데이터를 저장합니다.
- SQL 마이그레이션으로 테이블, 정책, 트리거를 관리합니다.
- KBO 동기화 기록과 서버 에러 로그도 저장합니다.

### 6.3 Supabase Edge Functions

- `sync-games`: KBO 경기 결과를 수집해 `game_histories`에 저장하고 실행 결과를 `kbo_sync_runs`에 기록합니다.
- `sync-lineups`: KBO 선발 투수와 라인업 정보를 수집해 `game_lineups`에 저장합니다.

### 6.4 Supabase Cron

- 경기 결과 동기화 작업을 예약 실행합니다.
- 라인업 동기화 작업을 예약 실행합니다.
- 푸시 알림 발송 API를 예약 호출합니다.
- 우천취소 등 경기 상태 변경을 더 빨리 반영하기 위해 오후 시간대 동기화도 포함합니다.

### 6.5 Supabase Vault 및 pg_net

- Cron 작업에서 필요한 비밀 값과 HTTP 호출에 사용됩니다.
- Supabase 내부에서 외부 API 또는 서비스 API를 호출하는 구조입니다.

### 6.6 KBO 데이터

- KBO 공식 웹 데이터를 크롤링하거나 API 형태로 요청해 경기 일정, 결과, 선발 투수, 라인업, 등록/말소 정보를 가져옵니다.
- 경기 결과 데이터는 저장 전 날짜, 팀, 점수, 취소 상태를 검증합니다.
- 이상 데이터는 저장하지 않고 `invalid_samples`에 예시를 기록합니다.

### 6.7 Open-Meteo

- 구장별 현재 날씨 정보를 가져옵니다.
- 미세먼지 PM10 정보를 함께 조회합니다.

### 6.8 Web Push

- 브라우저 푸시 알림 구독과 발송에 사용됩니다.
- 경기 라인업 알림과 직관 팁 알림을 제공합니다.

## 7. 전체 데이터 흐름

1. 사용자가 회원가입 또는 로그인합니다.
2. 사용자가 응원 팀을 선택합니다.
3. 선택한 팀 정보가 로컬 저장소와 Supabase 프로필에 저장됩니다.
4. 화면은 선택한 팀 기준으로 일정, 성적, 라인업, 구장 정보를 조회합니다.
5. Supabase Cron과 Edge Functions가 KBO 데이터를 주기적으로 동기화합니다.
6. 사용자는 직관 기록과 야구 일기를 저장합니다.
7. 알림을 허용한 사용자는 경기 전 라인업 알림과 직관 팁 알림을 받습니다.
8. 서버 API 오류가 발생하면 민감 정보를 가린 뒤 에러 로그에 저장합니다.
9. 운영자는 `npm run check:sync`와 `npm run check:errors`로 동기화와 에러 상태를 확인합니다.

## 8. API 권한 구분

| 구분 | API | 설명 |
| --- | --- | --- |
| 공개 API | 경기 일정, 경기 결과, 라인업, 로스터, 팀 성적, 구장 팁, 날씨 | 로그인 없이 조회 가능하며 요청 제한 적용 |

| 크론 전용 API | 알림 발송 API | `CRON_SECRET` 검증 필요 |
